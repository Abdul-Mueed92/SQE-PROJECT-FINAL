Control-flow complexity

The checkAmount() CFG evaluates currency difference, then amount above balance, then currency difference on the rejection path or equality on the accepted path. Its basic blocks are initial rounding and test, conversion, balance and cap test, rejection currency test, error conversion, throw, equality test, paid assignment, partial assignment and a common exit. With 13 edges and 10 nodes, McCabe complexity is 13 − 10 + 2 = 5. The local PHP parser independently found the same four decisions. The recurring currency predicate is correlated with the first one. Xdebug recorded six of eight syntactic paths. SonarQube reported 20 for the whole PHP file. The source-level sum is 5 for checkAmount(), 11 for prepareRequest(), and one each for the constructor, handle(), its transaction closure and createHistory(). Performance

On 28 November, k6 2.4.0 measured reads of one synthetic invoice on PHP 8.2.12, SQLite and the Windows loopback server. Each run warmed up for 15 seconds and measured 65 seconds. The test fixture used a 3,000 requests/minute API limit so ordinary throttling would not set throughput. The PHP built-in server has one worker; the workstation had 4 logical processors and 7.9 GiB RAM. The two runs at each load used the same build and freshly seeded synthetic data. Limits were p95 at most 350 ms for one user and 1,200 ms for five users, with fewer than 1% unexpected failures. The 350 ms one-user target is the interactive read budget; the 1,200 ms five-user target allows for concurrency while keeping a response usable. The failure cap protects reliable readback. These are project acceptance targets, not claims about an industry standard.
